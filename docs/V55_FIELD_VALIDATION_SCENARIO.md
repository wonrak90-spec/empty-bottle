# V55 Field Validation Scenario — WMS 선출력 / 차량 입고 / Pallet 실시간 OCR

## 목적
WMS 라벨을 입고 예정 수량에 맞춰 사전에 출력한 뒤, 차량 입고 시 실제 Pallet에 부착하는 현행 흐름을 기준으로 **차량 1대당 약 12 Pallet을 작업 흐름을 중단하지 않고 1개씩 실시간 인식·확인할 수 있는지** 검증한다.

정확도뿐 아니라 다음 세 가지를 동시에 검증한다.

1. **WMS 선출력 라벨 수량 ↔ 실제 입고 Pallet 수량 일치**
2. **WMS 라벨 ↔ 실제 Pallet/공급사 라벨의 오부착·혼착 방지**
3. **하차·도크·창고 이동 흐름을 방해하지 않는 실시간 처리 가능성**

## 적용 Candidate
- Vendor Parser: V55 3.6
- WMS Parser: V55 2.4
- Adaptive OCR: 2.4.3
- Candidate commit: 1d999d6cbf83ef2dfba10c70040371df8c75f3e7
- 운영 main 미적용 상태에서 현장 검증만 수행

## 현행 업무 흐름 기준

### 0. 차량 도착 전 — WMS 라벨 선출력
- 입고 예정 정보/수량을 기준으로 WMS 라벨을 미리 출력
- 예: 차량 1대 예상 12 Pallet이면 WMS 라벨 12매 준비
- 차량/입고번호/품목별로 출력 수량을 기록
- 시스템 Session에는 **예상 Pallet 수 + 선출력 WMS 라벨 수**를 함께 보유

### 1. 차량 입고
- 차량 도착
- 해당 차량/품목/입고 Session 선택

### 2. 실제 Pallet 수량 확인
- 실제 적재 Pallet 수량 확인
- 통상 차량 1대당 약 12 Pallet 기준
- **예상 Pallet 수 / 선출력 WMS 라벨 수 / 실제 Pallet 수** 3개를 비교

예:
- 예상 12
- WMS 라벨 출력 12
- 실제 Pallet 12
→ 정상 진행

예:
- 예상 12
- WMS 라벨 출력 12
- 실제 Pallet 11
→ 부착 전 수량 불일치 확인 필요

### 3. Pallet 하차
- Pallet을 차량에서 순차 하차
- 공급사 Pallet 라벨은 현물 식별 기준으로 사용

### 4. 도크 이동 + WMS 라벨 부착
- Pallet이 도크에서 정지한 상태에서 준비된 WMS 라벨 1매를 해당 Pallet에 부착
- **부착 직후 해당 Pallet을 OCR 확인 대상으로 전환**

### 5. Pallet별 실시간 OCR/매칭
권장 순서:

1. 공급사 Pallet 라벨 인식
   - 품명
   - 수량
   - Pallet No.

2. 부착한 WMS 라벨 인식
   - 입고번호
   - 품목코드
   - 품명
   - 입고수량
   - 용기번호/범위

3. 두 라벨의 공통 항목 자동 비교
   - 품명
   - 수량
   - 입고 Session/품목 일치 여부

4. 정상 → 즉시 저장
5. 불일치/저신뢰 → 검토대기
6. 다음 Pallet 하차/부착 작업은 계속

**핵심은 WMS 라벨을 단순히 OCR하는 것이 아니라, 선출력된 WMS 라벨이 실제 해당 Pallet에 올바르게 부착되었는지를 확인하는 것이다.**

### 6. Pallet 창고 이동
- 정상 완료 또는 현장 허용 상태 확인 후 Pallet 창고 이동
- 검토대기 건은 Pallet 위치/순번과 연결하여 사후 재확인 가능해야 함

## 권장 시스템 상태

차량 Session:
- 예상 Pallet: 12
- WMS 라벨 출력: 12
- 실제 Pallet: 12
- 부착/인식 완료: n / 12
- 정상: n
- 불일치: n
- 검토대기: n
- 수기수정: n
- 미사용 WMS 라벨: n

Pallet 상태:
- 01 / 12
- 공급사 라벨 OCR 완료 여부
- WMS 라벨 OCR 완료 여부
- 품명 일치
- 수량 일치
- Pallet No.
- WMS 입고번호
- WMS 용기번호
- 상태: 정상 / 불일치 / 검토대기 / 수기수정
- 촬영~저장 처리시간

## 반드시 필요한 통제

### 1. WMS 라벨 수량 통제
Session 종료 시 아래가 일치해야 한다.

**선출력 WMS 라벨 수 = 실제 부착/처리 Pallet 수 + 미사용/폐기 라벨 수**

라벨이 남거나 부족하면 종료 전 확인한다.

### 2. WMS 라벨 혼착 방지
- 다른 품목의 WMS 라벨 인식 시 즉시 불일치 경고
- 동일 WMS 입고번호/용기번호 중복 사용 경고
- 다른 차량 Session의 WMS 라벨 사용 시 경고

### 3. Pallet 중복/누락 방지
- 같은 Pallet No. 재인식 시 중복 경고
- 예상 12개 대비 11개만 완료된 상태에서 Session 종료 시 강한 경고
- 실제 Pallet 수와 처리 Pallet 수 불일치 확인

### 4. 수기수정 이력
작업자가 OCR 값을 변경하면:
- OCR 원본값
- 수정값
- 수정 항목
- 작업자
- 수정 시각
을 Learning Store에 기록한다.

## 현장 검증 Scenario

### Scenario 1 — 정상 차량 1대 / 12 Pallet
- WMS 라벨 12매 선출력
- 실제 Pallet 12개 확인
- 하차 → 도크 → WMS 라벨 부착 → OCR → 창고 이동
- 12/12 정상 매칭 여부 확인
- 목표: 하차 흐름 정지 없이 완료

### Scenario 2 — 실제 Pallet 수량과 선출력 라벨 수량 불일치
예:
- WMS 라벨 12매 출력
- 실제 Pallet 11개 입고

검증:
- 남는 WMS 라벨 1매를 시스템이 인지할 수 있는지
- 임의의 다른 Pallet에 라벨을 소진하는 행위를 방지할 수 있는지
- Session 종료 전 차이를 표시하는지

### Scenario 3 — WMS 라벨 혼착
- A Pallet에 B 품목의 WMS 라벨을 의도적으로 부착
- 공급사 라벨과 WMS 라벨 OCR 결과 비교
- 품명/수량/입고정보 불일치 즉시 경고 확인

### Scenario 4 — OCR 재시도 2~3건
- 12 Pallet 중 2~3건 기울기/반사/부분 가림
- 정상 Pallet은 계속 저장
- 실패 건은 검토대기로 분리
- 다음 Pallet 하차/라벨 부착을 막지 않는지 확인

### Scenario 5 — 수기 수정 1건
- OCR이 Pallet No. 또는 품명을 오인식
- 작업자가 수정 후 저장
- 수정 전/후 이력 100% 저장 확인

### Scenario 6 — 동일 Pallet/WMS 라벨 중복 처리
- 동일 Pallet 또는 동일 WMS 라벨을 다시 인식
- 중복 경고 및 중복 저장 차단 확인

### Scenario 7 — Peak 입고 시간대
제공된 지원 계획표 기준으로 오전 08:30~11:30에 여러 차량이 집중되는 날이 존재한다.

예: 09/28
- 까스병 오전 3대
- 판콜병 오전 2대
- 합계 오전 5대

차량당 약 12 Pallet 가정 시:
- **약 60 Pallet / 3시간**
- 단순 평균 약 3분 / Pallet

실제 차량은 균등 간격으로 도착하지 않을 수 있으므로 아래도 함께 검증한다.
- 차량 2대 연속 도착
- 24 Pallet 연속 처리
- 검토대기 Queue 최대치
- 다음 차량 도착 전 미처리 건수

## 합격 기준
1. 차량 1대 / 약 12 Pallet 처리 중 OCR 때문에 하차/부착/이동 작업이 중단되지 않을 것
2. 선출력 WMS 라벨 수량과 실제 Pallet 처리 수량의 차이를 추적할 수 있을 것
3. WMS 라벨 오부착/혼착을 공급사 라벨과의 비교로 검출할 수 있을 것
4. 정상 OCR 건은 현장 체감상 약 2초 수준을 목표로 할 것
5. 재시도 건이 발생해도 다음 Pallet 작업을 막지 않을 것
6. Pallet 누락 0건 / 중복 저장 0건 / WMS 라벨 중복 사용 0건
7. 수기 수정 건은 수정 이력 100% 기록
8. 차량 3대 이상 + Peak 시간대 연속 차량 시나리오를 추가 검증할 것

## 운영 가능 여부 판단
다음 조건이면 **실시간 병행 운영 가능**으로 판단한다.

- Pallet 하차/부착 주기보다 정상 OCR 처리시간이 충분히 짧음
- 재시도 건이 Queue로 분리되어 다음 Pallet 작업을 막지 않음
- Peak 시간대에도 검토대기 Queue가 지속적으로 증가하지 않음
- WMS 선출력 수 / 실제 Pallet 수 / 처리 수가 최종적으로 정합함
- 잘못된 WMS 라벨 부착을 시스템이 검출함

반대로 다음 중 하나가 반복되면 작업 방식 또는 화면 구조를 재설계한다.

- WMS 라벨 부착 후 OCR 때문에 Pallet 이동 대기 발생
- 검토대기 Queue가 다음 차량까지 누적
- WMS 라벨과 Pallet의 잘못된 매칭이 현장에서 검출되지 않음
- 라벨 잔량/누락 추적이 되지 않음

## 다음 검증 단계

- 새 사진/새 Source Group 기반 Final Holdout을 별도로 수행한다.
- 동시에 **WMS 선출력 → 실제 Pallet 확인 → 하차 → 도크 이동 → WMS 라벨 부착 → Pallet별 실시간 OCR → 창고 이동**의 Field Scenario를 수행한다.
- 최종 운영 판단은 OCR 정확도 + WMS 라벨 정합성 + 현장 처리량(throughput)을 함께 본다.
