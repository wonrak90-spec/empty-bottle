# V55 Field Validation Scenario — 차량 입고 / 12 Pallet 실시간 OCR

## 목적
차량 1대당 약 12개 Pallet을 실제 입고 작업 흐름을 중단하지 않고 작업자가 Pallet별로 1개씩 OCR 인식·확인할 수 있는지 검증한다.

## 적용 Candidate
- Vendor Parser: V55 3.6
- WMS Parser: V55 2.4
- Adaptive OCR: 2.4.3
- Candidate commit: 1d999d6cbf83ef2dfba10c70040371df8c75f3e7
- 운영 main 미적용 상태에서 현장 검증만 수행

## 실제 작업 흐름
1. 차량 입고
2. 총 Pallet 수량 확인 (통상 약 12개)
3. Pallet 하차
4. 도크 이동
5. Pallet 창고 이동

OCR은 위 흐름에 별도 공정을 추가하는 방식이 아니라, **Pallet이 도크에서 잠시 정지하는 순간 작업자가 1개씩 촬영·인식·확인하는 병행 작업**으로 설계한다.

## 권장 운영 시나리오

### A. 차량 단위 Session 생성
- 차량 입고 시 작업자가 신규 입고 Session을 시작
- 예상 Pallet 수량 입력: 예) 12
- 화면에 진행률 표시: 0 / 12

### B. Pallet별 실시간 OCR
각 Pallet 하차 후 도크 정지 시 아래 순서로 진행한다.

1. Pallet 라벨 촬영
2. 즉시 1차 OCR 수행
3. 품명 / 수량 / Pallet No. 자동 입력
4. 정상 인식 시 작업자가 확인 후 저장
5. 다음 Pallet로 즉시 진행

정상 건은 목표상 별도 키입력 없이 약 2초 수준에서 확인 가능하도록 한다.

### C. OCR 재시도/실패 건
재시도 또는 수기 수정이 필요한 건은 전체 하차 흐름을 멈추지 않는다.

- 해당 Pallet을 `검토대기` 상태로 저장
- 다음 Pallet 촬영을 계속 진행
- 하차 종료 후 또는 대기 시간에 검토대기 건 재확인
- 작업자가 수정한 값은 기존 Learning Store 정책대로 수정 전/후 값을 모두 기록

즉, **OCR 1건 실패 때문에 지게차/하차 작업 전체가 정지하지 않는 구조**를 기본으로 한다.

## 현장 안전 원칙
- 촬영/확인은 지게차 운전자가 운행 중 수행하지 않는다.
- Pallet이 정지한 상태에서 검수 담당자가 촬영한다.
- 촬영을 위해 하차 동선을 역행하거나 지게차 진행을 방해하지 않는다.

## 화면에 필요한 최소 정보
차량 Session 화면:
- 차량/입고 Session
- 예상 Pallet: 12
- 처리 완료: n / 12
- 정상: n
- 검토대기: n
- 수기수정: n

Pallet 카드:
- 순번: 01 / 12
- 품명
- 수량
- Pallet No.
- OCR 상태: 정상 / 재시도 / 수기수정
- 처리시간
- 저장시간

## 중복/누락 방지
- 같은 Pallet No. 재인식 시 중복 경고
- 예상 12개 대비 실제 저장 11개면 Session 종료 금지
- 예상 수량과 실제 수량이 다르면 종료 전 확인
- 수기 입력/수정 건은 별도 이력 저장

## 현장 검증 Scenario

### Scenario 1 — 정상 입고
- 차량 1대
- 12 Pallet
- 라벨 상태 양호
- 작업자가 하차 순서대로 12건 연속 OCR
- 목표: 작업 흐름 정지 없이 12/12 처리

### Scenario 2 — 2~3건 Adaptive 재시도
- 12 Pallet 중 2~3건 기울기/조명/부분 가림
- 정상 Pallet은 즉시 저장
- 재시도 건은 검토대기로 보내고 다음 Pallet 계속
- 목표: 대기열 누적이 실제 하차 속도를 넘지 않을 것

### Scenario 3 — 1건 수기 수정
- OCR 품명/Pallet No. 중 1개 필드 오인식
- 작업자가 수정 후 저장
- 수정 전/후 값 및 작업자/시간 기록 확인

### Scenario 4 — 중복 촬영
- 동일 Pallet을 실수로 2회 촬영
- 중복 Pallet No. 또는 동일 이미지/Session 조건으로 경고
- 중복 저장 방지

### Scenario 5 — 누락 Pallet
- 예상 12개 중 11개만 OCR 완료 상태에서 Session 종료 시도
- 종료 차단 또는 강한 경고
- 누락 확인 후 최종 종료

## 합격 기준
1. 차량 1대 / 약 12 Pallet 처리 중 OCR 때문에 하차 작업이 중단되지 않을 것
2. 정상 건 1차 인식은 현장 체감상 약 2초 수준 유지
3. 재시도 포함 건도 다음 Pallet 작업을 막지 않을 것
4. 12개 Pallet 중 누락 0건, 중복 저장 0건
5. 작업자 수정 발생 시 수정 이력 100% 기록
6. Session 종료 시 예상 Pallet 수량과 처리 수량 일치 확인
7. 현장 3대 이상 차량 반복 테스트 후 평균/최대 처리시간 및 대기 건수 집계

## 측정 항목
차량별로 아래 값을 저장한다.
- 총 Pallet 수
- 정상 OCR 수
- Adaptive 재시도 수
- 수기 수정 수
- Pallet별 OCR latency
- Pallet별 촬영~저장 완료 시간
- 최대 검토대기 건수
- 첫 Pallet 시작 ~ 마지막 Pallet 완료 총 시간
- 실제 하차 종료 시각
- OCR 작업이 하차 종료보다 늦어진 시간(있을 경우)

## 운영 가능 여부 판단
실제 하차 간격보다 OCR 처리/확인 시간이 짧거나, 재시도 건이 검토대기 Queue로 빠져 **대기열이 지속적으로 증가하지 않으면 실시간 병행 운영 가능**으로 판단한다.

반대로 Pallet 하차 간격보다 촬영·인식·확인 시간이 반복적으로 길어져 검토대기 Queue가 계속 쌓이면, 촬영 위치/작업자 역할/화면 조작 단계를 재설계한다.
